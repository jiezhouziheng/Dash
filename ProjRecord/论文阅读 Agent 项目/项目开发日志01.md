# 项目开发日志01：Paper-Reading-Agent 初步版本

日期：2026-05-21

## 1. 本次开发目标

本次开发围绕 Paper-Reading-Agent 的初步 MVP 展开，目标不是一次性完成完整论文智能体，而是先把最小可运行闭环搭起来，让项目具备可输入、可分析、可保存、可展示、可联调的基础能力。

最终形成的主流程是：

```text
前端输入论文信息
  -> 后端 API 接收 title / abstract / markdown_body
  -> 服务层生成 paper_id 并编排分析流程
  -> LLMClient 返回占位总结、术语表、学习计划
  -> FileStore 创建本地目录并保存文件
  -> 前端展示结构化分析报告
```

## 2. 已完成内容

### 2.1 明确 MVP 范围

当前版本只支持单篇论文输入，输入字段限定为：

- `title`：论文标题
- `abstract`：论文摘要
- `markdown_body`：论文正文或 Markdown 内容

暂时不做 PDF 解析、多论文管理、向量库、登录系统和真实大模型调用，避免过早扩大复杂度。

### 2.2 后端接口扩展

修改 `backend/app/api/routes.py`：

- 在 `PaperAnalyzeRequest` 中加入 `markdown_body` 字段。
- 将 `markdown_body` 从 API 层传入 `PaperService.analyze()`。

这一步打通了正文内容从前端进入服务层的数据路径。

### 2.3 业务服务层增强

修改 `backend/app/services/paper_service.py`：

- 新增 `_create_paper_id()`，根据论文标题和时间戳生成唯一论文编号。
- 在分析流程中创建论文专属工作区。
- 增加 `source` 字段，用于标识输入来源和正文字符数。
- 增加 `glossary` 和 `qa` 字段，使返回结构更接近项目需求文档。
- 将最终结果保存为 `analysis.json`。
- 生成基础 Markdown 阅读笔记 `reading_note.md`。

当前返回结果已经包含：

- `paper_id`
- `title`
- `source`
- `summary`
- `learning_plan`
- `glossary`
- `qa`
- `artifacts`
- `storage`

### 2.4 存储模块增强

修改 `backend/app/storage/file_store.py`：

- 新增 `prepare_paper_workspace()`，根据 `paper_id` 创建：
  - `data/papers/<paper_id>/`
  - `data/outputs/<paper_id>/`
- 新增 `save_json()` 和 `save_text()`，统一处理 JSON 与文本文件写入。

这一步让项目从“只返回接口结果”升级为“可以保留运行产物”。

### 2.5 LLM 占位能力补齐

修改 `backend/app/llm/client.py`：

- 保留论文总结占位输出。
- 保留学习计划占位输出。
- 新增 `extract_glossary()`，返回术语表占位数据。

当前 `LLMClient` 仍是模型调用边界，后续接入真实大模型时应优先只改该模块。

### 2.6 健康检查接口增强

修改 `backend/app/main.py`：

- `/health` 从只返回 `status` 扩展为返回：

```json
{
  "status": "ok",
  "service": "Paper-Reading-Agent"
}
```

该接口用于判断后端是否启动成功，也用于前端联调状态展示。

### 2.7 前端输入和展示增强

修改 `frontend/index.html`、`frontend/src/main.js`、`frontend/src/styles.css`：

- 增加 Markdown 正文输入框。
- 前端提交数据时加入 `markdown_body`。
- 增加后端状态提示。
- 页面加载时请求 `/health`，显示后端是否可用。
- 将接口返回的 JSON 渲染为可读阅读报告，而不是直接打印原始 JSON。
- 增加状态标签样式：等待、可用、不可用。

前端当前可以展示：

- 论文 ID
- 标题
- 来源信息
- 论文总结
- 术语表
- 学习计划
- 本地文件路径

### 2.8 文档更新

修改根目录 `README.md`、`backend/README.md`、`frontend/README.md`：

- 根目录 README 已重写为面向 GitHub 的高质量项目说明。
- 后端 README 增加健康检查说明。
- 前端 README 增加后端状态提示说明。

- 还没有 PDF 解析。

- 前端仍是静态页面，适合当前 MVP 阶段。
