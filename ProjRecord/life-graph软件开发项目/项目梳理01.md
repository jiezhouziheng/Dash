## 1. 这个项目是什么

Life Graph 是一个基于 Expo / React Native 的移动端应用，目标是做“生活记忆与关系图谱”。用户可以记录事件、人物、人物关系、情绪、分支标签和媒体资源，之后以图谱或时间线方式回看。

当前项目的重点还在移动端基础架构和本地优先数据底座：

- 跨平台 App：Expo 55、React Native 0.83、React 19、Expo Router。
- 状态与数据请求：React Query 5。
- 本地数据：expo-sqlite + drizzle-orm。
- 本地文件：expo-file-system，用于账号工作区和媒体文件。
- 会话安全存储：expo-secure-store。
- 全局运行时容器：Zustand。
- 测试：Jest + jest-expo。

需要注意：后端 API 目前还没有真正接入，`src/data/api-client.ts` 里的邮箱验证码、手机验证码、认证方法都是 stub，会抛 `METHOD_NOT_IMPLEMENTED`。当前最可用的登录路径是游客模式。

## 3. 代码目录怎么读

核心目录如下：

```text
src/
  app/                 Expo Router 路由入口
  screens/             页面级 UI
  components/          可复用 UI 组件
  features/            业务用例与页面 ViewModel Hook
  domain/              领域类型、接口、错误、值对象
  data/                数据层实现：DB、Repo、API、运行时 store
  config/              app 配置、React Query 配置、query key
  shared/              通用工具
  styles/              全局样式与色板
docs/                  团队开发、数据层、CI/CD、React Query 指南
__tests__/             单元测试
assets/                图片、图标等静态资源
```

项目采用比较清晰的分层：

```text
展示层 screen/component
  -> feature hook，例如 useAuthFlow / useSessionFlow / useBootstrapFlow
    -> service，例如 AuthService / SessionService / BootstrapService
      -> domain interface
        -> data implementation，例如 Repository / Transaction / ApiClient / Store
```

经验规则：

- UI 不直接碰数据库。
- 页面组件尽量只调用 `useXxxFlow()`。
- Service 负责编排业务流程。
- Repository 只负责读写具体表。
- `domain/` 放接口和类型，`data/` 放实现。

## 5. App 启动主链路

入口文件：

- `src/app/_layout.tsx`
- `src/app/index.tsx`
- `src/features/bootstrap/use-bootstrap-flow.ts`
- `src/features/bootstrap/bootstrap-service.ts`

启动过程：

1. `_layout.tsx` 创建全局 Stack，并用 `QueryClientProvider` 注入 React Query。
2. `index.tsx` 调用 `useBootstrapFlow()`。
3. `useBootstrapFlow()` 用 React Query 执行 `bootstrapService.execute()`，query key 是 `queryKeys.bootstrap`。
4. `BootstrapService.execute()` 做这些事：
   - 创建 `SessionStateStore`，从 SecureStore 加载本地 session。
   - 打开 app 级 SQLite：`life-graph-app-meta.db`。
   - 初始化 `DataAdapters`：`apiClient`、`appTransaction`、`accountTransaction:null`。
   - 创建 `appRuntime`，放进 `GlobalRuntimeStore`。
   - 如果没有 session，返回 `needs_login`，进入登录页。
   - 如果有 session，校验本地账号和绑定关系。
   - 校验通过后创建 account runtime，打开账号级数据库。
   - 如果账号配置里没有 `defaultPersonId`，自动创建一个默认 Person。
   - 返回 `ready`，进入主页面。

可以把启动链路理解为：

```text
App 启动
  -> bootstrap
    -> app runtime
      -> 是否有 session
        -> 无：login
        -> 有：validate session
          -> account runtime
            -> main tabs
```

## 6. 登录与会话链路

相关文件：

- `src/features/auth/use-auth-flow.ts`
- `src/features/auth/auth-service.ts`
- `src/features/session/session-service.ts`
- `src/data/app/session-state-store.ts`
- `src/data/api-client.ts`

当前支持三种入口：

- 邮箱验证码登录：UI 和流程已有，但 API stub 未实现。
- 手机验证码登录：UI 和流程已有，但 API stub 未实现。
- 游客登录：当前可用，会创建或复用本地 guest account。

游客登录流程：

```text
LoginScreen
  -> useAuthFlow.handleGuestLogin()
    -> AuthService.loginAsGuest()
      -> SessionService.loginAsGuest()
        -> appTransaction.run()
          -> localAccountRepo.findGuestAccount()
          -> 如果没有，createGuestAccount()
        -> sessionStateStore.setSession()
        -> 清空旧 account runtime
      -> bootstrapService.createAccountRuntime()
      -> 设置 accountTransaction 和 accountRuntime
      -> router.replace("/(tabs)")
```

已登录用户流程类似，但会先调用 `ApiClient.authenticate()`，拿到 `backendUserId/accessToken/refreshToken`，再建立 authenticated session。

关键提醒：现在 `ApiClient` 没实现，所以邮箱/手机路径会失败。开发认证功能时，优先改 `src/data/api-client.ts`，同时补 DTO、错误处理和测试。

## 7. 数据层核心设计

项目把数据分成两级：app 级数据和 account 级数据。

### 7.1 App 级数据

App 级数据存放在 `life-graph-app-meta.db`，生命周期属于整个 App。

Schema 文件：`src/data/app/db/app-meta-schema.ts`

主要表：

| 表 | 作用 |
| --- | --- |
| `local_accounts` | 本机本地账号空间，游客账号也是一种 local account |
| `backend_users` | 后端用户主体的本地缓存 |
| `local_account_bindings` | 本地账号和后端用户的绑定关系 |

对应 repo：

- `LocalAccountRepoImpl`
- `BackendUserRepoImpl`
- `LocalAccountBindingRepoImpl`

### 7.2 Account 级数据

Account 级数据是每个账号独立的业务空间，包含独立 SQLite、配置文件和媒体目录。

Schema 文件：`src/data/account/db/account-schema.ts`

主要表：

| 表 | 作用 |
| --- | --- |
| `persons` | 人物节点 |
| `relations` | 关系类型，例如朋友、同学 |
| `person_relations` | 人物之间的关系边 |
| `events` | 事件主体 |
| `event_persons` | 事件和人物的关联 |
| `branches` | 事件分支/主题标签，例如家庭、大学、旅行 |
| `event_branches` | 事件和分支标签关联 |
| `emotions` | 情绪标签 |
| `event_emotions` | 事件和情绪关联 |
| `media_assets` | 媒体资源注册表 |
| `event_assets` | 事件和媒体资源关联 |

远端 `dev` 里 `events` 比本地 `main` 多了一个 `color` 字段，并给 `title` 加了索引。开发前请以最新 `dev` 为准。

### 7.3 账号工作区

文件：`src/data/account/account-workspace-store.ts`

每个账号会在 `Paths.document/accounts/<localAccountId>/` 下有自己的工作区：

```text
accounts/<localAccountId>/
  config.json
  life-graph-account.db
  media/
```

`AccountWorkspaceStore` 负责：

- 确保目录存在。
- 读写 `config.json`。
- 导入媒体文件并计算 SHA256。
- 根据相对 `storagePath` 解析媒体 URI。
- 删除媒体文件。

远端 `dev` 文档里 `config.json` 已设计这些 key：

- `defaultPersonId`
- `accountAvatarAssetId`
- `bio`
- `birthday`
- `themeColor`
- `notificationEnabled`

但当前实现里默认 config 仍偏简单，实际开发时需要核对 `origin/dev` 的代码。

## 8. Runtime、Adapter、Transaction 的关系

这部分是项目最容易绕的地方。

### IDataAdapters

文件：

- `src/domain/interfaces/i-data-adapters.ts`
- `src/data/data-adapters.ts`

它是一个模块级容器：

```ts
{
  appTransaction,
  accountTransaction,
  apiClient
}
```

登录前 `accountTransaction` 是 `null`。登录或恢复 session 后，bootstrap 会把它替换成真实的 `AccountTransaction`。

### GlobalRuntimeStore

文件：`src/data/global-runtime-store.ts`

它是 Zustand 单例 store，保存：

- `appRuntime`：启动后存在，包含 session store 和 app 级 repos。
- `accountRuntime`：登录后存在，包含账号工作区和 account 级 repos。

### Transaction

文件：

- `src/data/app/app-transaction.ts`
- `src/data/account/account-transaction.ts`

Service 如果要做一组需要事务保护的数据写入，应通过：

```ts
dataAdapters.appTransaction.run(async ({ repositories }) => {
  // app 级 repo 操作
});

dataAdapters.accountTransaction?.run(async ({ repositories }) => {
  // account 级 repo 操作
});
```

事务内部会用当前 transaction db 创建一套 repository，避免外层 repo 和事务 repo 混用。

## 9. React Query 使用方式

项目约定：展示层不直接知道 React Query 的细节，而是通过 `useXxxFlow()` 获取数据、状态、错误和动作。

当前实际 query key：

- `queryKeys.bootstrap`
- `queryKeys.session.summary`

`docs/react-query-guide.md` 里已经写了更完整的目标方案，例如：

- `persons.all`
- `persons.detail(id)`
- `events.all`
- `events.detail(id)`
- `graph.byCenter(personId)`

后续新增人物、事件、图谱功能时，应把 query key 统一放进 `src/config/query-keys.ts`，不要在组件里手写字符串。

推荐模式：

```text
Screen
  -> useEventFlow / usePersonFlow
    -> useQuery + useMutation
      -> EventService / PersonService
        -> transaction + repositories
```

写操作成功后，在 mutation 的 `onSuccess` 里统一 `invalidateQueries`，不要让页面之间互相手动刷新。

## 10. 错误和值对象

错误类：

- `src/domain/errors/app-error.ts`
- `src/domain/errors/business-error.ts`
- `src/domain/errors/validation-error.ts`
- `src/shared/normalize-error.ts`

值对象：

- `EmailAddress`
- `PhoneNumber`
- `VerificationCode`

这些值对象会在 feature hook 里创建，用于输入校验。例如邮箱会 trim + lower-case，验证码会校验格式。UI 层拿到错误后通过 `normalizeAppError` 统一展示。

开发新表单时建议沿用这个模式：输入先变成 VO / primitive，再交给 service。

## 13. 你可以从哪些任务切入

按难度从低到高：

1. 跑通项目和游客登录
   - 切到最新 `dev`。
   - `npm ci`。
   - `npm run start`。
   - 用 Expo Go 或模拟器进入游客模式。

2. 熟悉路由和页面壳
   - 从 `src/app/_layout.tsx` 看有哪些页面。
   - 从 `src/app/(tabs)/_layout.tsx` 看底部 Tab。
   - 从 `src/screens/main/graph-screen.tsx` 看首页图谱 UI。
   - 从 `src/components/modals/add-record-modal.tsx` 看新建入口。

3. 接入人物创建功能
   - 新增或扩展 `PersonService`。
   - 扩展 `IPersonRepo` / `PersonRepoImpl`。
   - 新增 `usePersonFlow()` 或 `usePersonEditor()`。
   - 把 `PersonFormScreen` 从占位改为真实表单。
   - 成功后 invalidate `persons` / `graph` 相关 query。
   - 补 service 和 repo 测试。

4. 接入事件创建功能
   - 扩展 `IEventRepo`，目前 `EventRepoImpl` 只有 `findById`。
   - 处理事件与人物、情绪、分支、媒体的关联写入。
   - 这类写操作应该放进 `accountTransaction.run()`。
   - 注意 `event_persons` 等关联表的唯一约束和软删除。

5. 接后端认证
   - 实现 `src/data/api-client.ts`。
   - 明确 base URL、请求格式、token 刷新策略。
   - 补失败状态、网络错误和 DTO 测试。

6. 图谱真实渲染
   - 先定义 Graph VO：nodes、edges、centerPersonId、关系强度、事件数量等。
   - 新增 graph service，把 persons / relations / events 组装成 UI 可消费数据。
   - 再选择图谱渲染方案。

## 14. 开发时特别容易踩的点

- 不要在 `main` 上开发。当前本地就在 `main`，正式做功能前先切 `dev`。
- 不要基于本地 `main` 的 UI 判断最新状态，远端 `dev` 已经有大量页面更新。
- 邮箱/手机登录现在会失败，因为 API stub 未实现。
- 登录前 `accountRuntime` 和 `accountTransaction` 可能为空，account 级功能必须处理运行时未初始化。
- 写 account 级业务数据时，应优先走 `accountTransaction.run()`。
- 软删除字段普遍是 `deletedAt`，查询有效数据时要过滤 `deletedAt is null`。
- 媒体资源表存相对路径，不要把绝对文件路径直接写进数据库。
- `docs/react-query-guide.md` 里的部分 query key 是目标设计，不是当前 `query-keys.ts` 的完整现状。
- 当前 `drizzle.config.ts` 只指向 app-meta schema，account schema 的迁移需要特别确认团队约定。

## 15. 一句话理解这个项目

这是一个“本地优先的生活记忆图谱 App”。底层已经搭好账号、会话、本地数据库、账号工作区和基础路由；远端 `dev` 已经开始铺图谱、人物、事件相关页面壳。接下来最有价值的开发工作，是把人物/事件/图谱的 UI 占位接到真实 account 级数据层，并继续补 React Query flow 和测试。
