# 关系管理实现第一版

生成时间：2026-05-24

## 1. 实现边界

本次只实现关系管理职责内的功能：

- 人物创建、编辑、列表、详情卡片。
- 人物头像从相册导入、保存到账号 workspace 的 media 目录，并写入 `media_assets`。
- 人物详情中点击头像可原比例预览。
- 删除人物增加二次确认；默认使用 `ghost` 策略，只软删除人物本身，保留其在事件中的参与记录和关系记录。
- 补齐人物/关系相关 repo 接口与数据实现，使其满足“新建人物、编辑人物、人物列表详情”的最小能力。

没有实现事件编辑、事件详情完整卡片、图谱可视化布局、搜索弹窗、筛选弹窗、AI 助手等模块。这些属于其他分工或后续版本。

## 2. 依赖变化

新增依赖：

- `expo-image-picker`

用途：

- 在人物表单和人物详情弹窗中调用系统相册选择图片。

## 3. Domain 接口补齐

### 3.1 `IPersonRepo`

文件：`src/domain/account/repositories/i-person-repo.ts`

新增能力：

- `findByIdIncludeDeleted(personId)`
- `findByIds(personIds)`
- `findByIdsIncludeDeleted(personIds)`
- `listActivePersons()`
- `searchByName(query)`
- `save(person)`
- `update(person)`
- `softDelete(personId, deletedAt)`

说明：

- 无后缀查询只返回活跃人物，即 `deletedAt IS NULL`。
- `IncludeDeleted` 查询用于 ghost 展示或关联数据回显。
- 保留原有 `create(person)`，实现中委托给 `save(person)`，兼容旧调用。

### 3.2 `IRelationRepo`

文件：`src/domain/account/repositories/i-relation-repo.ts`

新增能力：

- `findByIds(relationIds)`
- `findByName(name)`
- `listActiveRelations()`
- `create(relation)`

说明：

- `findByName` 用于保存人物时复用已有关系类型，避免重复创建同名 active relation。
- `listActiveRelations` 用于人物编辑页展示已有关系标签快捷选择。

### 3.3 `IPersonRelationRepo`

文件：`src/domain/account/repositories/i-person-relation-repo.ts`

新增能力：

- `findByPersonId(personId)`
- `findByPersonIdIncludeDeletedPerson(personId)`
- `findByPersonIdAndRelationFilter(personId, relationId)`
- `findByPairAndRelation(personAId, personBId, relationId)`
- `save(personRelation)`
- `update(personRelation)`
- `softDelete(personRelationId, deletedAt)`
- `softDeleteByPersonId(personId, deletedAt)`

说明：

- `findByPersonId` 会过滤对方人物已删除的关系。
- `findByPersonIdIncludeDeletedPerson` 不过滤对方人物删除状态，用于 ghost 关系展示。
- `save` 内部会规范化人物对顺序，满足 schema 中 `personAId < personBId` 的约束。

### 3.4 `IEventPersonRepo`

文件：`src/domain/account/repositories/i-event-person-repo.ts`

新增能力：

- `findByPersonId(personId)`
- `softDeleteByPersonId(personId, deletedAt)`

说明：

- `findByPersonId` 只返回 active event_person 且事件未删除的记录，用于人物详情“共同记忆”的最小数据来源。
- `softDeleteByPersonId` 只在 `clean` 删除策略中使用。本次 UI 默认走 `ghost`，不会清理事件参与记录。

### 3.5 `IMediaAssetRepo`

文件：`src/domain/account/repositories/i-media-asset-repo.ts`

新增能力：

- `save(mediaAsset)`

说明：

- 人物头像导入后，先通过 `AccountWorkspaceStore.importMedia` 复制文件，再用该接口写入 `media_assets`。

## 4. Data 实现细节

### 4.1 PersonRepoImpl

文件：`src/data/account/repositories/person-repo-impl.ts`

关键实现：

- `listActivePersons` 按 `updatedAt DESC` 返回活跃人物。
- `searchByName` 使用 SQLite `LIKE %query%`，空 query 返回空数组。
- `findByIds` 和 `findByIdsIncludeDeleted` 对空数组直接返回 `[]`，避免生成无效 SQL。
- `softDelete` 只设置 `deletedAt` 和 `updatedAt`，不物理删除。

### 4.2 RelationRepoImpl

文件：`src/data/account/repositories/relation-repo-impl.ts`

关键实现：

- `listActiveRelations` 按关系名升序返回。
- `findByName` 只查 active relation。
- `create` 直接插入 `relations`。

### 4.3 PersonRelationRepoImpl

文件：`src/data/account/repositories/person-relation-repo-impl.ts`

关键实现：

- `normalizePersonPair` 保证写入关系时两端 ID 顺序稳定。
- `findByPersonId` 使用 `innerJoin persons` 过滤对方已删除人物。
- `findByPersonIdIncludeDeletedPerson` 只过滤关系边自身的 `deletedAt`，保留 ghost 关系。
- `softDeleteByPersonId` 会软删除以该人物为任一端点的 active 关系边。

### 4.4 EventPersonRepoImpl

文件：`src/data/account/repositories/event-person-repo-impl.ts`

关键实现：

- `findByPersonId` join `events`，只返回事件仍 active 的参与记录。
- `softDeleteByPersonId` 支持 clean 删除策略，但当前 UI 不主动调用 clean。

### 4.5 MediaAssetRepoImpl

文件：`src/data/account/repositories/media-asset-repo-impl.ts`

关键实现：

- `save` 插入 `media_assets`。
- `findById` 保持只返回 active media asset。

### 5.2 RelationService

文件：`src/features/relation/relation-service.ts`

核心方法：

- `listPeople()`
- `getCreatePersonEditorVO()`
- `getEditPersonEditorVO(personId)`
- `savePerson(vo)`
- `getPersonCard(personId)`
- `updatePersonAvatar(personId, avatarLocalUri)`
- `deletePerson(personId, strategy)`
- `searchPersons(query)`

关键规则：

- 新建人物：生成 person id，保存人物，按输入关系创建/复用 relation，再创建 `person_relations`。
- 编辑人物：只同步“默认人物与被编辑人物之间”的关系，不误删该人物与其他人的关系。
- 头像保存：`importMedia` 复制文件到 `avatars` 子目录，写 `media_assets`，再更新 `person.avatarAssetId`。
- 详情弹窗更换头像：使用 `updatePersonAvatar`，只改头像，不触碰人物关系，降低误改风险。
- 删除人物：`ghost` 只 soft delete person；`clean` 会额外清理 `event_persons` 和 `person_relations`。
- UI 当前二次确认后调用 `ghost`，符合“其他事件中的记录、数据保留”的要求。

## 7. 删除策略说明

本次需求要求：

> 删除人物节点后，无法再访问该人物节点，但是该人物节点的人物在其他事件中的记录、数据等做保留。

因此 UI 采用 `ghost` 策略：

1. `personRepo.softDelete(personId, now)`
2. 不清理 `event_persons`
3. 不清理 `person_relations`

效果：

- 人物列表和搜索不会再出现该人物。
- 直接按 active `findById` 查不到该人物。
- 事件模块未来如果使用 `IncludeDeletedPerson` 类查询，可以展示 ghost 人物记录。

`clean` 策略保留在 service 中，供未来“同时清理参与记录”选项使用。

## 10. 后续对齐点

- 事件模块后续展示参与人时，如果要保留被删除人物的历史记录，应使用 IncludeDeletedPerson 类查询。
- 图谱模块如果只展示 active 节点，应使用 active person 查询；如果需要 ghost 边，需要明确 UI 表现。
- 未来如果产品要在删除人物时提供“同时清理事件参与信息”选项，可在确认弹窗中切换 `ghost` / `clean` 策略。
- 当前共同记忆只展示 event id，占位等待事件卡片 VO/Service 完成后替换为正式事件卡片。
